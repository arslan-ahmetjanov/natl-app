# Что осталось до 1.0.0

Список задач между 0.9.0 и 1.0.0. 1.0.0 — это обещание: сценарии, папки
и настройки, созданные в 1.0.0, продолжают работать в 1.x. Поэтому в список
попадает не только функциональность, но и то, что делает обещание выполнимым.

Обозначения: **S** — до дня, **M** — несколько дней, **L** — неделя и больше.

## Блокеры: без них 1.0.0 не выпускаем

### 1. Браузер на чистой машине (L)

Сейчас Playwright берётся из системной установки. На новом компьютере запись
и прогон падают.

Сделать: скачивание Chromium при первом запуске в `userData`, прогресс,
повтор при обрыве, понятная ошибка про прокси и офлайн.

Готово, когда: чистая Windows-виртуалка без Playwright → установка → запись →
зелёный прогон, без ручных команд.

### 2. Формат заморожен и описан (M)

Сейчас формат существует в коде и docs, но не описан как контракт.

Сделать: `docs/format.md` — структура папок (`tests/`, `pages/`, `artifacts/`),
правила имён, что считается ломающим изменением, как читать старые файлы.

Готово, когда: по документу сторонний человек пишет сценарий и ресурсы,
не открывая исходники приложения.

### 3. Релизный конвейер (M)

Сейчас релиз собирается руками на одной машине.

Сделать: GitHub Actions на тег — линт, тесты, сборка, артефакты, контрольные
суммы, черновик релиза. Сборка не выпускается, если тесты красные.

Готово, когда: тег → через N минут на релизе лежат установщик, портативная
версия и `sha256`.

### 4. Подпись или официальный отказ (M + внешние сроки)

Сейчас установщик неподписанный, SmartScreen пугает пользователя.

Сделать: либо сертификат (OV/EV или Azure Trusted Signing), либо запись
в документации: «сборка неподписанная, проверяйте сумму, вот почему».

Готово, когда: `npm run verify:sign` показывает `Valid` либо решение об
отказе зафиксировано в `docs/compliance/signing.md` и в релизе.

### 5. Восстановление после сбоя (S)

Сделать: кнопка «сохранить журнал» в файл, восстановление из `.bak`
в интерфейсе, проверка целостности файлов при открытии папки.

Готово, когда: пользователь может отдать разработчику один файл с журналом
и вернуть предыдущую версию сценария без ручных действий в проводнике.

## Качество

### 6. Сквозные проверки в CI (S)

Скрипты `smoke:natl` и `smoke:record` уже есть. Подключить их в конвейер
и сделать обязательными для релиза.

Готово, когда: красный smoke блокирует сборку.

### 7. Тесты интерфейса (M)

Проверить поведением: список сценариев, редактор и автосохранение, окружение,
диалог шага, восстановление после битого YAML.

Готово, когда: ключевые экраны покрыты тестами на React Testing Library,
а не только ручной проверкой.

### 8. Линтер знает больше (S)

Сейчас: разбор, глаголы, обязательные поля. Добавить: неизвестные `imports`,
`do:` на несуществующее действие, дубликаты имён в ресурсах, пустые
селекторы.

Готово, когда: типичные ошибки ловятся до запуска, а не в браузере.

### 9. Бюджет производительности (S)

Один чанк 659 КБ из-за CodeMirror. Вынести редактор в ленивую загрузку.

Готово, когда: основной бандл под 300 КБ, первый экран открывается без
задержки на слабой машине.

### 10. Доступность (S)

Фокус, подписи у иконок, клавиатура в меню и вкладках, контраст
в «Полигоне» (оранжевый на графите).

Готово, когда: все действия достижимы с клавиатуры, контраст текста
не ниже 4.5:1.

## Продукт

### 11. Linux-сборка (M)

AppImage и deb из CI. Решение: входит в 1.0.0 или после — см. вопросы ниже.

### 12. macOS (M)

dmg без подписи, только сборка в CI. Кандидат на «после 1.0.0».

### 13. Автообновление (M)

electron-updater поверх GitHub Releases, с каналом `prerelease` для 0.x.

### 14. История прогонов (M)

Сейчас видны только артефакты последнего прогона. Нужен список прогонов
с датой, статусом и ссылкой на кадры, очистка по расписанию.

### 15. Импорт старых папок TestBlox (S/M)

Конвертер JSON → YAML есть в коде, но не подключён к интерфейсу. Либо
подключить, либо удалить код и написать в документации, что старые папки
не поддерживаются.

### 16. Вставка ресурса в открытый сценарий (S)

Сейчас кнопка копирует текст. Сделать: вставка `imports` и `do:` прямо
в текущий сценарий одним нажатием.

### 17. ИИ-агент: предсказуемость (M)

История переписки, показ диффа перед записью файла, лимит стоимости
на сессию, инструменты для `pages/`, а не только для `tests/`.

## Документация и поставка

### 18. Руководство пользователя (M)

Установка, первый сценарий, ресурсы, прогон в CI, разбор ошибок,
горячие клавиши. На русском, со скриншотами.

### 19. Сайт (S/M)

Опубликовать (нужен публичный репозиторий или отдельный публичный `docs/`),
обновить скриншоты и тексты под «Полигон».

### 20. CHANGELOG и политика поддержки (S)

Что считается ломающим изменением, сколько живут старые версии,
как сообщать об ошибках.

## Определение готовности 1.0.0

Релиз считается 1.0.0, когда одновременно выполнено:

- [ ] чистая машина проходит путь «установка → запись → прогон» без ручных команд;
- [ ] формат описан и заморожен, есть правило миграции;
- [ ] релиз собирается конвейером, артефакты с суммами, smoke зелёный;
- [ ] вопрос подписи закрыт: подписано или официально отражено в документации;
- [ ] журнал можно выгрузить и восстановить предыдущую версию файла;
- [ ] есть руководство пользователя и CHANGELOG;
- [ ] список известных ограничений опубликован.

4. **Автообновление** — в 1.0.0 или после?
5. **Приоритет**: сначала надёжность (пункты 1–10) или сначала Linux и macOS?
