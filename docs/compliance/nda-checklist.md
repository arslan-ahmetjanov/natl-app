# Чек-лист перед публикацией

Проходить перед каждым публичным релизом, публикацией в npm и показом на защите.

## Код

- [ ] `npm run check:nda` — следов работодателя нет
- [ ] В репозитории нет внутренних доменов, адресов API, имён хостов
- [ ] Нет конфигов из рабочего контура: `.env`, ключи, сертификаты, дампы
- [ ] Нет закомментированных фрагментов внутренних систем
- [ ] Демо-данные вымышленные: логины, адреса, названия компаний

## История

- [ ] История git сохранена, даты не переписаны
- [ ] Теги релизов на месте
- [ ] Автор коммитов — личный аккаунт
- [ ] В сообщениях коммитов нет названий внутренних задач и тикетов

## Документы

- [ ] README не упоминает работодателя и внутренние продукты
- [ ] В документации нет цифр из внутренних отчётов
- [ ] Лицензия указана явно (MIT для публичной части)
- [ ] `docs/compliance/origin-and-rights.md` обновлён

## Согласование

- [ ] Письменное согласие работодателя на публикацию получено
- [ ] В согласии перечислено, какие части публикуются
- [ ] Понятно, что внутренние доработки остаются закрытыми

## Сборка

- [ ] Артефакты подписаны (см. `signing.md`)
- [ ] В установщике нет путей и имён рабочего контура
- [ ] Версия и changelog соответствуют содержимому
