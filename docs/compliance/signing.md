# Подпись сборки

Неподписанный установщик Windows показывает предупреждение SmartScreen и выглядит
подозрительно. Подпись убирает предупреждение и позволяет проверить, что файл
не изменён после сборки.

Подпись — это не «настройка в коде». Нужен сертификат, выданный удостоверяющим центром.

## Варианты сертификата

| Вариант | Что нужно | Сроки | Цена |
|---|---|---|---|
| OV Code Signing | организация или ИП, проверка личности | 1–3 недели | от ~40 тыс. ₽/год |
| EV Code Signing | то же плюс токен или HSM | 2–4 недели | дороже, репутация сразу |
| Azure Trusted Signing | аккаунт Azure, проверка личности | несколько дней | дешевле, подпись через облако |

Самоподписанный сертификат предупреждение SmartScreen **не убирает** — он годится
только для внутренних проверок.

## Как включить подпись в сборке

`electron-builder` подписывает автоматически, если заданы переменные окружения.
Код менять не нужно:

```powershell
$env:CSC_LINK = "C:\certs\natl.pfx"        # путь к файлу или base64
$env:CSC_KEY_PASSWORD = "пароль-сертификата"
npm run build
```

Для CI те же значения кладутся в секреты репозитория и передаются в шаг сборки.

Проверить результат:

```powershell
npm run verify:sign
```

Скрипт покажет статус подписи и издателя для собранного установщика.

## Azure Trusted Signing

Облачная подпись без файла сертификата. Требуется аккаунт Azure, профиль подписи
и CLI `trusted-signing-cli`. Подключение делается через JS-конфиг electron-builder
(`electron-builder.config.js`) с хуком `win.sign`, который вызывает CLI. Файл
`package.json` для этого не подходит: там нельзя хранить функцию.

Порядок:

1. Создать в Azure ресурс Trusted Signing и профиль сертификата.
2. Установить `@azure/trusted-signing-cli`.
3. Добавить в конфиг сборки хук, который вызывает CLI с параметрами аккаунта.
4. Проверить подпись тем же `npm run verify:sign`.

## Что подписывать

- `NATL Setup <версия>.exe` — установщик.
- `NATL <версия>.exe` — портативную версию.
- Пакеты npm подписываются иначе: через provenance и `npm publish --provenance`,
  это отдельная история и к сертификату Windows отношения не имеет.

## Проверка перед релизом

- [ ] Сертификат действует и не истёк
- [ ] Переменные окружения заданы в среде сборки, а не в репозитории
- [ ] `npm run verify:sign` показывает `Valid` и ожидаемого издателя
- [ ] Пароль сертификата не попал в git и в логи CI
