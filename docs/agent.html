Агент

@natl/agent превращает git diff в черновик NATL YAML через LLM с OpenAI-совместимым API, а потом прогоняет его через ту же проверку, что и natl validate. Он не заменяет написание тестов руками и не заменяет natl run.

Что делает

natl run отвечает: проходит ли сценарий? natl-agent отвечает: какой дымовой тест стоит предложить для этого пул-реквеста?

  1. Сравнивает ветку с базовой
  2. Разбирает изменения семантически (Tree-sitter и эвристика как запасной путь)
  3. Берёт примеры из существующих YAML в test_roots
  4. LLM → JSON или YAML → нормализация → валидация
  5. При желании запускает самопочинку
  6. Публикует: комментарий в PR или вывод в лог

Установка и настройка

npm install -D @natl/agent @natl/cli

Создайте natl-agent.yml (ключи API в репозиторий не коммитьте):

llm:
  provider: openai   # openai | ollama | azure | custom
  endpoint: https://api.openai.com/v1
  api_key: ${LLM_API_KEY}
  model: gpt-4o-mini
  parameters:
    temperature: 0
  json_mode: true
mode: stdout
test_roots: [tests, examples]
self_healing:
  enabled: false
  max_retries: 2

Локальная Ollama: provider: ollama, endpoint: http://127.0.0.1:11434/v1, json_mode: false. Примеры: examples/natl-agent.*.yml.

Первый локальный запуск

export LLM_API_KEY=sk-...   # для Ollama не нужно
natl-agent --config natl-agent.yml --mode stdout --base origin/main

Скопируйте черновик в tests/, поправьте селекторы и адреса, затем natl validate и natl run.

GitHub Actions

Шаблон: examples/.github/workflows/natl-agent.yml. Нужны fetch-depth: 0, секрет OPENAI_API_KEY и pull-requests: write для mode: comment.

- uses: actions/checkout@v4
  with:
    fetch-depth: 0
- uses: ./agent
  with:
    openai_api_key: ${{ secrets.OPENAI_API_KEY }}
    base_ref: origin/${{ github.base_ref }}
    mode: comment
    config: natl-agent.yml

В своём репозитории либо копируйте composite action из дерева NATL, либо установите CLI: npm install -g @natl/agent и вызывайте natl-agent отдельным шагом. Смотрите examples/.github/workflows/natl-agent.yml.

GitLab CI

Шаблон: examples/ci/gitlab-ci.yml. По умолчанию NATL_AGENT_MODE=stdout — пробный прогон в логе джобы. Для комментария в MR поставьте NATL_AGENT_MODE=comment и masked-переменные LLM_API_KEY и GITLAB_TOKEN.

Jenkins

Шаблон: examples/ci/Jenkinsfile. Учётные данные llm-api-key; параметры AGENT_MODE и COMMENT_PROVIDER (auto / github / gitlab / stdout).

Сгенерировать и прогнать в CI

  • Джоба A — natl-agent: предложение и проверка валидации, публикация комментария или вывод в лог
  • Ревью — человек переносит YAML в tests/
  • Джоба B — natl run по принятому набору (как в руководстве и примерах CI)

Не коммитьте черновики в main без ревью. Если нужен пробный прогон черновика, оставьте его артефактом workflow и запускайте validate там — это не источник истины для набора тестов.

Ограничения и ревью

  • Пустой или неподдерживаемый diff → предложений мало или нет
  • Небольшие локальные модели годятся только для проверки конвейера; в CI берите уровень gpt-4o-mini или Ollama от 3B
  • Агент не ослабляет проверку: самопочинка пробует ещё раз, но невалидный сценарий всё равно отклоняется
