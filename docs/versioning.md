# Версии

Две разные линейки, их нельзя путать.

## Приложение (NATL IDE)

`apps/desktop` — продукт в разработке, поэтому версия до 1.0.0.

Сборка распространяется как **community**: неподписанная, без поддержки
и без автообновления. Канал виден в интерфейсе рядом с номером версии.

| Диапазон | Что значит |
|---|---|
| `0.x.y` | предварительные сборки: интерфейс и формат ещё меняются |
| `1.0.0` | первый стабильный релиз: обещание совместимости для сценариев и настроек |

Правила до 1.0.0:

- `0.x.0` — новая функциональность или заметное изменение интерфейса;
- `0.x.y` — исправления и мелкие правки;
- ломающие изменения допустимы, но описываются в релизе;
- тег — `v0.x.y`, артефакты — `NATL Setup 0.x.y.exe`.

После 1.0.0 действует semver без исключений: ломающее изменение — только мажор.

## Движок и пакеты (`@natl/*`)

Пакеты `@natl/core`, `@natl/cli`, `@natl/adapter-*`, `@natl/agent` —
отдельный продукт, уже опубликован с версией **1.0.0** и замороженным API
(см. `core/docs/api-1.0.md`). Эта линейка не перезапускается: контракт
используют внешние проекты.

Что из этого следует: приложение `0.9.x` может зависеть от `@natl/core 1.0.0`.
Это нормально и означает «новый интерфейс поверх стабильного движка».

## Почему вернулись с 3.x на 0.x

Сборки 2.x и 3.x были внутренними итерациями без обещаний совместимости.
Нумерация 3.0.0 создавала ложное впечатление зрелости: три мажора за неделю —
это не зрелость, а перебор вариантов. Теги остались в истории, но новая
линейка начинается с 0.9.0 и идёт к 1.0.0.

## Порядок выпуска

1. Обновить версию в `apps/desktop/package.json`.
2. `npm run test:natl && npm run lint` в `apps/desktop`.
3. `npm run build`.
4. Тег `vX.Y.Z`, пуш тега.
5. Релиз на GitHub с артефактами и короткими заметками.
