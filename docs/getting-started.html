Установка

Два способа работать с NATL: приложение и CLI. Формат сценариев один.

Приложение NATL IDE

Windows-сборка: запись кликов, редактор с автокомплитом и проверкой, окружение с локаторами, прогон со скриншотами, ИИ-агент. Скачать в релизах.

  1. Установить приложение и открыть папку проекта (или создать новый).
  2. Нажать «Записать», ввести адрес и пройти путь руками.
  3. Файл появится в tests/; «Run» покажет шаги и кадры.

Тот же файл запускается в CI командой natl run tests/ — приложение и CLI используют один движок @natl/core.

CLI

Нужен Node.js 18 или новее.

npm install -g @natl/cli @natl/adapter-playwright
npx playwright install chromium
natl --version

Если вывелась версия — всё готово. Если нет, смотрите раздел Ошибки.

Начать проект с нуля (пример открывает живую песочницу):

mkdir my-tests && cd my-tests
natl init
natl run tests/

Доступ к песочнице: demo@natl.dev / secret. Офлайн-версия рядом с проектом: examples/fixtures/sandbox.html (задайте base_url в natl.config.yaml).

Первый прогон

После natl init команда natl run tests/ открывает песочницу, входит и дергает статический JSON API. Для адреса на GitHub Pages нужен интернет, либо направьте base_url на локальную копию.

В репозитории есть пример входа на локальном HTML-файле:

git clone https://github.com/natl-dev/natl.git
cd natl/examples
natl run login.yaml

Должно появиться PASS. Испортите текст проверки, запустите снова, прочитайте ошибку и верните как было. Это самый быстрый способ увидеть, как выглядит падение.

Из чего состоит сценарий

name: Sandbox login smoke
engine: playwright
tags: [smoke]
timeout: 15000
retries: 0
vars:
  base_url: ./fixtures/sandbox.html
  user: demo@natl.dev
  pass: secret
steps:
  - goto: $base_url
  - fill: "#email"
    with: $user
  - fill: "#password"
    with: $pass
  - click: "#login-btn"
  - assert: ".welcome"
    text: "Welcome, demo"

Поля в начале файла:

ПолеЧто делает
nameПоказывается в отчёте; по нему работает --grep
tagsИспользуются с --tags
engineplaywright, selenium, cypress или http
timeoutТаймаут шага по умолчанию, в миллисекундах
retriesСколько раз повторять сценарий целиком после падения
varsЗначения, к которым обращаетесь как $name
secretsОткуда брать секреты
importsДругие YAML-файлы, которые подключаются
elements / actionsЛокаторы объектов страниц и именованные сценарии
locator_strategyСтратегия для строковых селекторов: css или xpath
casesОтдельный прогон на каждую строку
dataМассив, доступный как $data для for:
before_each / after_eachШаги до и после основного блока на каждой попытке
stepsСами шаги

Отдельный шаг тоже может задавать timeout, save или debug. Чтобы сменить движок посреди прогона, оберните шаги в with:. Один engine: у шага контекст не переключает.

Конфиг проекта и окружения

Значения по умолчанию живут в natl.config.yaml рядом с тестами (NATL ищет файл вверх по дереву папок):

engine: playwright
browser: chromium
timeout: 15000
base_url: https://staging.example.com
headless: true
viewport: { width: 1280, height: 720 }
locator_strategy: css
artifacts_dir: artifacts
retries: 0
trace: on-fail
video: off
soft_assert_screenshot: false

Разные стенды без правки каждого сценария:

natl run tests/ --env staging
natl run tests/ --config config/prod.yaml

--env staging загружает config/staging.yaml. Передавать --env и --config одновременно нельзя.

Приоритет от сильного к слабому: флаги CLI, поля в файле теста, профиль окружения, natl.config.yaml, встроенные значения.

Шаги UI

ШагЗамечания
gotoАдрес http(s), file:// или относительный путь к локальному файлу
click / tapОдно и то же действие. Пишу click:
fillЛокатор, затем with: со значением
selectЛокатор и значение варианта через with:
check / uncheckФлажок и переключатель
waitЗадержка в мс или селектор с visible, hidden, attached, detached
 
- goto: $base_url
- fill: "#email"
  with: $user
- select: "#country"
  with: "KZ"
- check: "#agree"
- click: "#submit"
- wait: 500
- wait: ".modal hidden"

Клики, ввод и проверки сами ждут элемент до timeout. Писать wait: ".ok visible" прямо перед проверкой почти не нужно. Оставьте wait: для пауз и состояний вроде hidden.

Проверки

- assert: ".welcome"
  text: "Hello"              # is: работает так же
- assert: ".welcome"
  contains: "Hell"
- assert: $welcome
  visible: true
- assert: ".banner"
  hidden: true
- assert: ".price"
  attr: class contains "sale"
- assert: current_url == "https://example.com/app"
- assert: current_url contains "/app"
- assert: $ping.status == 200
- assert: ".price"
  text: "$10"
  soft: true
- soft_assert: ".stock"      # то же, что soft: true
  visible: true

В attr: можно использовать ==, !=, contains и matches. Жёсткая проверка останавливает прогон. Мягкие продолжают работу и валят прогон в конце, если хоть одна не прошла.

Чтение значений, set, log, скриншот

- get_text: ".title"
  save: title
- get_attr: "a"
  attr: href
  save: href
- set: $total = $price * $qty
- log: "total=$total"
- log: { message: "x", level: warn }   # info, debug, warn, error
- debug: true
- screenshot:
    file: artifacts/shot.png
    full_page: true

Прокрутка, свайп, долгое нажатие

Работает одинаково на десктопе и в мобильном вебе. Ветвить по типу устройства не нужно.

- scroll: "#footer"
  into_view: true            # или delta_x / delta_y
- swipe: "#carousel"
  direction: left            # left, right, up, down
  distance: 200
- long_press: "#card"
  duration_ms: 700

Переменные, секреты, выражения

ЗаписьЗначение
$userПеременная
$order.idВложенное поле
$env.KEYИз окружения или .env (ошибка, если нет)
$secret.KEYТот же источник; скрывается в логах
${ENV:KEY}Старая запись; продолжает работать
 
secrets:
  env:
    file: .env
    encoding: utf-8

vars:
  user: $env.TEST_USER
  pass: $secret.TEST_PASS

Сравнения: == != > < >= <= contains matches and or not.

Функции: now, today, random_int, random_string, random_uuid, random_email, len, contains, trim, upper, lower, replace, match, join, map, filter, range.

Во время проверок адреса доступна current_url. Рабочий пример — examples/env_login.yaml.

Объекты страниц

# pages/login.yaml
locator_strategy: css
elements:
  email: "#email"
  title:
    strategy: xpath
    value: "//h1"
actions:
  login:
    - fill: $email
      with: $user
    - fill: "#password"
      with: $pass
    - click: "#login-btn"

# сценарий
imports:
  - pages/login.yaml
steps:
  - goto: $base_url
  - do: login.login
    user: $user
    pass: $pass
  - include: login/login
    vars: { user: $user }

В обычных сценариях используйте do: page.action. include: — нижний уровень, когда нужен путь к файлу или подключение файла целиком. Дополнительные ключи рядом с do: становятся переменными для действия.

Файл страницы может содержать только elements и actions, без steps. При прогоне папки NATL пропускает pages/ и config/.

Стратегия локатора выбирается по порядку: объект элемента, файл страницы, конфиг проекта, css.

Кейсы и данные

cases:
  - { name: user1, user: "a@test.com", pass: secret, expect: "Welcome, A" }
  - { label: user2, user: "b@test.com", pass: secret, expect: "Welcome, B" }
steps:
  - fill: "#email"
    with: $user
  - assert: ".welcome"
    text: $expect

data:
  - { name: one }
  - { name: two }
steps:
  - for: $item in $data
    steps:
      - log: $item.name

Для таблицы входных данных используйте cases:. Для перебора списков и range — data: вместе с for:. В отчёт попадает name или label строки, а если нет ни того ни другого — [case N].

HTTP

engine: http
vars:
  base_url: http://127.0.0.1:8765
steps:
  - get: $base_url/get
    save: ping
  - post: $base_url/post
    headers: { X-Test: "1" }
    body: { hello: world }
    save: echo
  - put: …
  - patch: …
  - delete: …
  - assert: $echo.status == 200
  - assert: $echo.ok == true

Сохраняется { status, headers, body, ok }. Относительные адреса используют vars.base_url, если это http(s)-адрес. Старая форма api: ещё разбирается, но в новых файлах используйте глаголы выше.

UI и HTTP в одном сценарии:

engine: playwright
steps:
  - goto: $base_url
  - with: http
    steps:
      - get: $api_base/get
        save: ping
      - assert: $ping.status == 200
  - click: "#refresh"

HTTP-примеры в репозитории ждут локальную заглушку:

node stubs/echo-server.mjs
natl run http_only.yaml
natl run ui_http_block.yaml

if / for / repeat / parallel

- if: $role == "admin"
  then:
    - click: "#admin"
  else:
    - click: "#user"

- for: $i in range(1, 5)
  steps:
    - log: $i

- repeat: 3                 # или "3 times", или times: 3
  steps:
    - click: "#next"        # $i задаётся на каждой итерации

- repeat:
    until: $done == true
  steps:
    - click: "#poll"        # остановится после 1000 итераций

- parallel:                 # wait: all по умолчанию, можно any
  - get: $api/a
    save: a
  - get: $api/b
    save: b

before_each и after_each выполняются вокруг steps на каждой попытке, включая повторы.

Теги, повторы, CLI

name: Checkout
tags: [smoke, checkout]
retries: 1
natl run tests/ --tags smoke,auth    # совпадение по любому тегу
natl run tests/ --grep "Login"       # регулярка по имени или пути
natl run tests/ --retries 2
natl run tests/ --env staging
natl run tests/ --headed
natl run tests/ --engine selenium
natl run tests/ --trace on-fail
natl run tests/ --video off

Если передать --tags и --grep вместе, файл должен совпасть по обоим. Нет совпадений — код выхода 1. Повтор запускает сценарий целиком с новым контекстом браузера. Результат определяет последняя попытка.

Как писать шаги

Пишите обычный YAML с соседними ключами. Этого ждут редакторы и схема:

- fill: "#email"
  with: $user
- wait: ".dashboard visible"
- assert: ".welcome"
  text: "Hello"

Есть и однострочная форма, которую раннер понимает. Многие редакторы пометят её как невалидный YAML, поэтому в репозиторий такое лучше не коммитить:

- fill: "#email" with: $user
- assert: ".welcome" text: "Hello"
- scroll: $footer into_view

Для автодополнения укажите расширению YAML схемы из @natl/core. Настройка yaml.schemas описана в README CLI.
